# 모아 — 개인 재무 관리

로그인 없이 컴퓨터 한 대에서 사용하는 한국어 가계부입니다. 프론트엔드와 백엔드는 JavaScript로 작성했으며, Windows와 macOS에서 같은 소스를 사용합니다.

## 실행

Node.js 24 이상이 필요합니다. 프로젝트 폴더에서 아래 명령을 실행하세요. `.nvmrc`에는 Node.js 24를 지정했습니다.

### macOS

터미널에서 프로젝트 폴더로 이동한 뒤 실행합니다.

```bash
cd "/프로젝트가/있는/경로/Expense"
npm ci
npm run dev
```

실행 스크립트를 사용해도 됩니다.

```bash
bash start-dev.command
```

Finder에서 더블클릭으로 실행하려면 최초 한 번 `chmod +x start-dev.command`로 실행 권한을 부여하세요. Node.js를 셸 버전 관리자로 설치했다면 터미널에서 실행하는 방법을 권장합니다. Finder 실행 환경에서는 해당 Node.js의 PATH를 찾지 못할 수 있습니다.

Apple Silicon 및 Intel Mac으로 프로젝트를 옮길 때에는 **Windows의 `node_modules`와 `dist`를 복사하지 말고**, 소스와 `package-lock.json`을 옮긴 뒤 Mac에서 `npm ci`로 설치하세요. Vite 빌드 도구의 플랫폼별 의존성은 Mac에서 새로 설치해야 합니다.

### Windows

```powershell
npm.cmd ci
npm.cmd run dev
```

`start-dev.cmd`를 더블클릭해 실행할 수도 있습니다. 최초 의존성 설치는 위의 `npm.cmd ci`로 진행하세요.

### 접속 및 종료

브라우저에서 **http://127.0.0.1:4173** 으로 접속합니다. 개발용 프론트엔드(4173)와 API(3001)가 함께 실행됩니다. 터미널에서 `Ctrl+C`를 누르면 종료됩니다.

### 빌드 후 실행

빌드 후에는 Express 서버 하나로 사용할 수 있습니다.

macOS:

```bash
npm run build
npm start
```

Windows:

```powershell
npm.cmd run build
npm.cmd start
```

이 경우 접속 주소는 **http://127.0.0.1:3001** 입니다. 두 실행 방식을 동시에 사용하면 API 포트가 충돌하므로 하나만 실행합니다.

## 기능

- 수입 내역 / 지출 내역 별도 메뉴 및 전용 등록·수정·삭제 화면
- 이체 내역 별도 메뉴: 계좌 기준 입금·출금 구분, 검색·방향 필터, 수입·지출·예산 합계에서 제외
- 표 중심의 업무용 UI: 월 합계, 조회 합계, 검색·필터, 고정 헤더, 명시적 수정·삭제 버튼
- 월별 수입·지출·월 수지·예산 잔액
- 최근 6개월 추이, 카테고리별 지출 비중과 상세 내역
- 월별 지출 예산과 사용률, 초과 금액
- 월별 카테고리 예산 직접 입력, 카테고리별 실제 지출·잔액 비교
- 수입·지출 카테고리 추가, 이름 변경, 삭제
- 고정지출 예정 항목: 항목명, 금액, 지급일, 카테고리, 결제수단
- 고정지출과 실제 지급 내역 연결, 지급 상태, 중복 반영 방지, 지난달 항목 복사
- 기존 지출을 고정지출로 등록하고 지급 완료로 연결
- 내역 검색, 수입/지출 및 카테고리 필터, 최신순/금액순, 목록 무한 스크롤
- 수입 화면에 전월 대비 수입 증감 표시
- 전체 기록과 예산의 JSON 백업 및 복원
- 실제 데이터와 분리된 메모리상의 데모 모드
- 작은 화면에 대응하는 반응형 UI, 키보드로 사용 가능한 대화상자
- XLSX 두 번째 시트에서 수입·지출·이체 가져오기: 월 다중 선택, 원본 미리보기, 중복 방지

원화 정수 금액을 사용합니다. 월 수지는 해당 월 수입에서 지출을 뺀 값으로, 계좌 잔액이나 이월 잔액이 아닙니다. 날짜와 기본 조회 월은 사용하는 컴퓨터의 현지 날짜를 따릅니다.

거래·고정지출·카테고리의 삭제 버튼은 확인창 없이 바로 처리합니다.

수입·지출 목록은 처음 30건을 표시하고, 페이지 전체를 아래로 스크롤하면 30건씩 이어서 표시합니다. 표의 세로 높이 제한은 없으며, 좁은 화면에서는 표를 가로로 스크롤할 수 있습니다. 이체 목록은 표 안을 아래로 스크롤하면 30건씩 이어서 표시합니다. 월·검색·필터·정렬을 바꾸면 목록이 처음으로 돌아갑니다. 내역 수정·삭제 시에는 펼쳐 본 범위를 유지합니다. 조회 합계는 현재 표시된 건수와 관계없이 검색·필터 결과 전체를 기준으로 계산합니다.

수입·지출 목록의 `수정` 또는 내용 클릭으로 해당 행에서 날짜·내용·카테고리·수단·금액을 바로 편집할 수 있습니다. 취소·환급 여부와 고정지출 연결도 수정할 수 있습니다. `저장`(Enter)으로 반영하고 `취소`(Esc)로 되돌립니다. 저장에 실패하면 입력 내용을 유지하고 오류를 표시합니다.

메모 입력·표시·검색 기능은 제공하지 않습니다. 기존 기록 및 엑셀 원본의 메모 값은 백업 호환성과 중복 검사를 위해 내부적으로 보존합니다.

## 엑셀 가져오기

1. `데이터 관리 → 엑셀 수입·지출·이체 가져오기`로 이동합니다. 이체 화면의 `엑셀 가져오기` 버튼으로도 이동할 수 있습니다.
2. `sample` 폴더의 파일을 선택하고 `파일 읽기`를 누릅니다. `다른 XLSX 파일 선택`으로 컴퓨터의 파일을 직접 선택할 수도 있습니다. 파일 크기는 최대 10MB입니다.
3. 두 번째 시트의 월별 신규 수입·지출·이체 건수, 수입·지출 합계, 이체 입출금 금액, 환급 건수와 중복/제외 건수를 확인합니다. **가져올 월을 하나 이상 체크**하세요. 여러 월 선택과 전체 선택을 지원합니다.
4. 선택한 월의 원본 행, 내용, 분류 및 결제수단을 미리보기에서 확인한 뒤 `선택한 월 가져오기`를 누릅니다. 미리보기만으로는 데이터가 저장되지 않습니다.

지원 형식은 sample의 뱅크샐러드 내보내기 형식입니다. 시트 이름과 관계없이 **두 번째 시트**를 읽습니다. 처음 20행 안에서 `날짜`, `타입`, `내용`, `금액`, `화폐`, `결제수단` 헤더를 찾으며, `시간`, `대분류`, `소분류`, `메모`도 보존합니다.

- `타입`이 수입, 지출 또는 이체인 원화(KRW) 내역을 가져옵니다. 0원, 다른 통화, 잘못된 행은 사유와 함께 제외합니다.
- 이체의 양수 금액은 해당 계좌의 입금, 음수 금액은 출금으로 보존합니다. 원본의 각 행을 저장하며 입출금 쌍을 추정해 합치거나 상대 계좌 기록을 자동 생성하지 않습니다. 수입·지출·월 수지·예산 사용액에는 포함하지 않습니다.
- 이체를 제외하던 이전 버전에서 가져온 파일은 다시 읽고 같은 월을 선택하세요. 기존 수입·지출의 중복 검사 키가 유지되어 빠진 이체 내역만 추가할 수 있습니다.
- 원본 지출 금액은 음수가 정상 지출, 양수가 취소·환급입니다. 환급은 지출 메뉴에 남고 지출 합계에서 차감됩니다. 수입의 음수 금액은 수입 취소로 처리합니다. 금액 입력란은 절댓값이며 `취소·환급` 체크로 합계 부호를 구분합니다.
- 원본 대분류·소분류, 카드/계좌 이름, 메모, 시간, 파일명과 행 번호를 보존합니다. 앱 카테고리로 대응되지 않는 분류는 기타 수입·지출에 연결하고 원본 분류를 함께 표시합니다.
- 동일 원본 내역은 파일을 다시 읽거나 파일명을 바꾸어도 중복으로 넣지 않습니다. 동일 내용의 반복 행은 파일 안에서 나타난 횟수로 구분합니다. 원본 내용이 변경된 행이나 수동 등록 내역은 동일 거래로 자동 추정하지 않습니다.
- 기존 기록에 **추가**하며 예산 및 고정지출 예정 항목을 만들거나 덮어쓰지 않습니다. 원본 분류가 `고정`인 지출도 실제 거래로 가져오며, 필요하면 기존 고정지출 계획에 직접 연결할 수 있습니다.
- 가져오기는 선택한 월 전체를 한 DB 트랜잭션으로 저장합니다. 실패 시 일부만 저장되지 않습니다. 원본 XLSX 파일은 수정하지 않습니다.
- 미리보기는 서버 메모리에 30분간 유지됩니다. 서버를 재시작하거나 만료되면 파일을 다시 읽어야 합니다.
- 백업에는 환급 여부와 중복 검사 정보도 포함됩니다. 예전 버전 앱으로 새 백업을 복원하면 새 필드를 지원하지 않으므로 최신 소스를 사용하세요.

## 예산 및 고정지출

1. `예산 · 고정지출`에서 조회 월을 고르고 `총예산 설정`으로 해당 월 전체 지출 한도를 입력합니다. 고정지출도 이 총예산에 포함합니다. 0원은 예산 미설정을 의미합니다.
2. `카테고리별 예산` 표에 한도를 입력하고 `카테고리 예산 저장`을 누릅니다. 고정지출을 포함한 한도이며 월마다 별도로 저장됩니다. 빈칸은 미설정, 0원은 지출 한도 0원을 뜻합니다. 카테고리 예산 합계와 총예산의 미배정/초과 배정 금액을 표시하며, 월 총예산은 별도로 관리합니다.
3. `고정지출 추가`로 월세, 보험료, 통신비 등을 등록합니다. 항목은 선택한 달에만 적용됩니다. 31일처럼 해당 월에 없는 지급일은 말일로 표시됩니다.
4. 실제 지급했다면 항목 옆의 `지출 등록`을 눌러 실제 금액과 날짜를 확인해 저장합니다. 이미 기록한 지출이 있다면 지출 내역의 수정 화면에서 `고정지출 연결`을 선택합니다. 한 항목에는 같은 달 지출 한 건만 연결할 수 있습니다.
5. 기존 일반 지출 행을 우클릭한 뒤 `고정지출 등록`을 선택하면 거래의 월·금액·날짜·분류·수단으로 새 예정 항목을 만들고, 그 거래를 지급 완료로 연결합니다. Mac에서는 트랙패드의 보조 클릭으로 같은 메뉴를 열 수 있습니다. 실제 거래를 추가하지 않아 지출액이 중복되지 않습니다. 이미 연결된 고정지출과 취소·환급은 등록 대상에서 제외됩니다.
6. 다음 달에는 `지난달 항목 복사`를 사용할 수 있습니다. 예정 항목만 복사하고 실제 지급 기록이나 지급 완료 상태는 복사하지 않습니다. 중복 방지를 위해 이번 달 항목이 없을 때만 사용할 수 있습니다. 자동 반복 생성은 하지 않습니다.

계산 기준:

- 예산 잔액 = 총예산 − 실제 지출
- 추가 사용 가능액 = 총예산 − 실제 지출 − 미지급 고정지출 예정액
- 일반 지출 배정 가능액 = 총예산 − 고정지출 예정 합계

고정지출을 지급 처리하면 예정액 대신 실제 지급액이 계산되므로 이중 차감하지 않습니다. 예정 금액을 수정해도 이미 등록한 실제 금액은 바뀌지 않습니다. 실제 지급 내역을 삭제하거나 연결을 해제하면 예정 항목은 다시 미지급 상태가 됩니다. 예정 항목만 삭제하면 실제 내역은 일반 지출로 유지됩니다.

## 카테고리 편집

`데이터 관리 → 카테고리 관리`에서 수입·지출 구분을 선택해 추가하거나, 기존 이름을 수정하고 저장합니다. 이름 변경은 모든 월의 내역·필터·예산·분석에 반영됩니다. 기존 카테고리의 수입·지출 구분은 변경하지 않습니다.

카테고리를 삭제하면 연결된 거래와 고정지출은 같은 구분의 기본 카테고리(기타 수입/기타 지출)로 이동하고, 월별 카테고리 예산도 합쳐집니다. 원본 거래 금액과 엑셀 분류 정보는 보존됩니다. 기본 기타 카테고리는 이름만 수정할 수 있습니다.

## 데이터 보관

실제 기록은 `data/ledger.sqlite`에 저장됩니다. 앱을 재시작해도 유지됩니다. 데모는 새로고침하거나 종료하면 사라집니다.

`데이터 관리 → JSON 백업`으로 모든 기록, 카테고리, 월별·카테고리별 예산, 고정지출 항목과 연결 정보를 저장하세요. 복원 시 **현재 데이터 전체가 백업 내용으로 교체**됩니다. 복원 전 확인 화면이 표시되며, 잘못된 백업은 기존 데이터를 변경하지 않습니다. 복원은 SQLite 트랜잭션으로 처리합니다. 새 백업은 이체 내역과 방향까지 보존하는 버전 4입니다. 버전 1·2·3 백업도 지원합니다. 버전 1·2는 카테고리를 기본 목록으로, 카테고리 예산을 빈 목록으로 복원하며 버전 1은 고정지출 목록도 비워집니다.

SQLite 파일 자체를 복사할 때에는 먼저 서버를 종료하세요. 실행 중에는 WAL 파일도 쓰이므로 JSON 백업 기능을 사용하는 것이 좋습니다.

Windows와 Mac 사이에서 기록을 옮길 때에는 기존 컴퓨터에서 JSON 백업을 내보낸 뒤, 새 컴퓨터의 `데이터 관리 → 백업 파일 선택`으로 가져오세요. 운영체제와 관계없이 같은 백업 형식을 사용합니다.

서버는 `127.0.0.1`에만 바인딩되며 외부 Host/Origin 및 교차 사이트 요청을 차단합니다. 사용자 계정, 클라우드 동기화, 외부 분석 도구는 없습니다. 실행 중 외부 폰트/CDN 요청도 사용하지 않습니다. 패키지 최초 설치에만 네트워크가 필요합니다. 데이터는 로컬 파일이며 암호화되어 있지는 않습니다.

## 기술 구성

| 영역 | 구성 |
| --- | --- |
| 프론트엔드 | React, Vite |
| 백엔드 | Express |
| 저장소 | Node.js 내장 `node:sqlite`의 SQLite |
| 데이터 동기화 | TanStack Query |
| 차트 | Recharts |
| 아이콘 | Lucide React |
| 대화상자·우클릭 메뉴 | Radix Dialog, Context Menu |
| 알림 | Sonner |
| 검증 | Zod — 프론트·백엔드 공용 스키마 |
| 날짜 | date-fns |
| XLSX 파싱 | read-excel-file (로컬 Node.js 서버) |
| 동시 개발 서버 | concurrently |

Node.js 24의 내장 SQLite는 실행 시 실험적 API 경고를 출력할 수 있습니다.

## 코드 및 검증

- `src/`: React 화면과 스타일
- `server/`: Express API와 SQLite
- `shared/ledger.js`: 검증, 집계, 카테고리, 데모
- `tests/`: API·영속성·복원·집계·입력 검증 테스트

macOS:

```bash
npm test
npm run build
```

Windows:

```powershell
npm.cmd test
npm.cmd run build
```

테스트는 별도의 메모리 DB 및 임시 DB를 사용하며 실제 가계부 데이터를 변경하지 않습니다.

현재 자동 테스트와 빌드는 Windows에서 검증했습니다. macOS 실기기 실행은 아직 검증하지 않았습니다.
